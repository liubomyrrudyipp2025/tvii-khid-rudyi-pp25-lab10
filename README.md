# Твій Хід — накопичувальний навчальний сайт

Рудий Л. Д., ПП-25. Поточне робоче дерево на етапі ЛР12: збережено функції попередніх лабораторних, медіакомпоненти ЛР10 та планувальник ЛР11; оптимізовано доставку ресурсів, збільшено зони взаємодії й додано конфігурацію CI/CD. Папки й релізи попередніх робіт — історичні знімки одного продукту, а не незалежні сайти. Історична назва npm-пакета та папки ЛР10 збережена для сумісності.

## Компоненти

- Повернуті з реально випущеної ЛР6: три навчальні картки з характеристиками й поясненням рекомендації; локальний пошук за назвою, стан відсутності результатів; додавання/видалення в демо-кошику, узгоджені лічильники та reset після reload. Жодного оформлення, backend, мережевого надсилання або збереження вибору.
- Накопичувальна навігація: desktop «Сервіс», mobile native menu з Escape/outside dismissal та поверненням фокуса; прямі переходи до форми, карти, Smart Select і прикладів. Header закріплюється на всіх ширинах, якірні переходи мають відступ; skip-link явно фокусує main, вибрана radio-картка виділяється в обох темах.
- Статичні інформаційні блоки з ЛР5–6: разова покупка, подарунок і Smart Select з полями ціни/складу/умов без вигаданих значень; чотири дії локальної демо-підписки доступні на account.html (заміна, пропуск, пауза, скасування).

- Повна темна/світла тема: палітра ЛР3, клавіатурний перемикач; вибір теми зберігається окремо від локальних демо-профілів.
- Hero: 8 окремих варіантів — горизонтальні та вертикальні фото й відео для темної і світлої тем. Комп’ютер використовує горизонтальні ресурси, телефон (до 767 px) — вертикальні. Фото за замовчанням — відповідний макет ЛР3, а не відеопостер. Відео завантажується лише після вибору, без звуку; мобільні кліпи 9:16 показуються повністю, без обрізання або розтягування.
- Основа коробки у восьми варіантах Hero має узгоджені положення й масштаб за початковим кадром: застосовано рівномірну CSS-підгонку оригіналів. На телефоні навмисно залишаються смуги фону, щоб показати джерела повністю; на комп’ютері збережено фонове cover-полотно з обрізанням країв. Карти, жетони й рух усередині різних оригіналів не стають тотожними; це не обіцянка піксельної однаковості всієї анімації.
- «Ігрові вечори»: три ілюстративні фото Pavel Danilyuk / Pexels через офіційний CDN, одне повне фото на будь-якій ширині, ручна навігація без автопрокрутки. Оригінали фото не поширюються у проєкті; потрібна мережа. Джерела — `CREDITS.md`.
- YouTube: англомовний огляд «Top 10 Essential Board Games Everyone Should Own» — Board Game Hangover.

- Swiper 11.2.10: шість явно вигаданих відгуків, 1/2/3 видимі слайди, loop, autoplay 3500 мс, стрілки, пагінація й ручна пауза. Hover, фокус, прихована вкладка та reduced-motion зупиняють автоматичне відтворення.
- GLightbox 3.3.1: кнопка «Збільшити ілюстрацію» у режимі фото Hero відкриває чотири наявні варіанти графіки ЛР3 (три оригінальні JPEG і світлу мобільну ілюстрацію у WebP), модальний перегляд і навігація. Це альтернатива Fancybox, а не використання Fancybox; погодження заміни викладачем не заявляється.
- Typed.js 2.0.12: три фрази в Hero, керування паузою та статичний доступний текст. Після переходу до reduced-motion залишається безпечний статичний варіант до перезавантаження.
- Успадкована форма: п’ять чистих валідаторів, стани полів, нативний діалог, Escape, повернення фокуса та reset.

Версії зовнішніх бібліотек зафіксовані в CDN-адресах. Для анімованих компонентів потрібен доступ до CDN; за його відсутності залишається статичний текст/зображення. CSS Tailwind 3.4.17 компілюється локально: Play CDN у production не використовується.

Масштаб галереї залежить від режиму GLightbox: на desktop click-zoom збільшує зменшені зображення, але не розтягує вже показані 1:1. На ширинах до 768 px використовується pinch-zoom. У pinned GLightbox 3.3.1 після переходів між слайдами повернення до початкового розміру може потребувати сильнішого зведення пальців, а не строго симетричного жесту. Swipe працює між сусідніми зображеннями, а циклічний перехід через край альбому — кнопками навігації.

## Планувальник ігрового вечора (ЛР11)

Чотири параметри: ціла кількість учасників 2–12, доступний час 15–240 хв, тривалість паралельного раунду 15/30/45/60 хв та необов’язкові 5-хвилинні перерви між раундами. Групи до чотирьох осіб збалансовані (5 → 3+2). Якщо раунд довший за доступний час, результат 0 є валідним. Дроби, порожні поля та значення поза межами відхиляються зі зрозумілими повідомленнями; неповний DOM лишає компонент неактивним, не ламаючи іншу справну копію.

Формула: `g = ceil(p/4)`, `r = floor((t+b)/(d+b))`, `used = r ? r*d+(r-1)*b : 0`, `free = t-used`, `games = r*g`. Після останнього раунду перерви немає. Результат оновлюється через input/change без кнопки «Розрахувати»; reset повертає 4/120/30/true. Це план часу, а не підбір конкретних ігор чи бронювання.

`js/widget.js` ізольовано замиканням; чистий `calculatePlan(raw)` також експортується для Node. Вивід — через textContent. Значення планувальника не надсилаються, не зберігаються і не журналюються. Початкова AI-версія, приватні QA-докази й звіти зберігаються окремо від репозиторію та dist.

## Оптимізація та доступні зони взаємодії (ЛР12)

- Темні Hero-фото мають окремі повнокадрові WebP для mobile/desktop; початкові JPEG збережено для HQ-альбому. Перекодування не змінює розміри й пропорції кадру.
- Локальну таблицю шрифтів підключено через stylesheet link замість CSS `@import`; зовнішні скрипти медіакомпонентів завантажуються з `defer` у визначеному порядку.
- Пагінація відгуків має окремі 48 px комірки з малими видимими точками. Для основних посилань і кнопок використано прозоре розширення hit-area без збільшення видимих іконок; label перерв і зовнішні посилання мають власну мінімальну висоту. Це цільовий контракт цього прототипу, а не твердження про повну відповідність WCAG.
- Lockfile містить сумісне транзитивне виправлення `postcss-selector-parser` 6.1.5; прямі версії інструментів і назву пакета збережено. Поточний стан відомих advisory можна перевірити командою `npm audit`.

## Локальний демо-акаунт, підписка та квіз

- Три сторінки: `index.html`, `quiz.html`, `account.html`. У хедері завжди є «Увійти / реєстрація» й «Демо-підписка»; окремий модуль оформлення та керування — `account.html#subscription`.
- Профіль створюється за вигаданим псевдонімом (2–40 символів), без пароля або email. Вхід — вибір існуючого профілю у цьому браузері; можна вийти та увійти знову. Це НЕ захищена автентифікація: будь-хто з доступом до браузера може вибрати профіль.
- `localStorage` key `tvii-khid-demo-service-v1` зберігає лише псевдоніми, поточний демо-вхід і стани підписок. Немає сервера, платежів, email-підтвердження, реальних замовлень або синхронізації між пристроями. Використовуйте тільки вигадані дані. Демо-дані можна видалити окремою дією з підтвердженням, не очищуючи тему сайту.
- Демо-підписка: оформлення без оплати, заміна гри, пропуск/повернення наступного бокса, призупинення/відновлення, скасування та нове оформлення. Стани залишаються після reload. На паузі заміна/пропуск недоступні.
- Квіз: 5 питань, назад/далі, перевірка відповіді, випадково одна з трьох явно вигаданих навчальних ігор. Відповіді відображаються у підсумку, але не надсилаються й не зберігаються. Це випадковий демо-вибір, не персоналізований алгоритм. Гість бачить необов’язкову пропозицію зареєструватися після результату, увійдений профіль — посилання на підписку.
- Планувальник має явне пояснення автоматичного перерахунку та кнопку «Скинути параметри»; його бізнес-логіка не змінена.

## Локальний запуск

Потрібні Node.js >=18 із npm та Python >=3.11. У VS Code налаштовано Live Server на `127.0.0.1:5510`, без автоматичного відкриття браузера. Відкрийте `index.html` та виконайте `Live Server: Open with Live Server`.

Окремий запуск зібраного сайту без розширення Live Server:

```bash
npm ci
npm run package:dist
python -m http.server 5511 --bind 127.0.0.1 --directory dist
```

Адреса цього окремого сервера: `http://127.0.0.1:5511/`.

```bash
python -m unittest discover -s tests -v
node --test tests/validation.test.cjs tests/planner.test.cjs
```

Тести джерел і валідаторів не замінюють перевірку взаємодій у браузері. Автоматизований viewport не є фізичним пристроєм або ручним screen-reader тестуванням.

## Приватність і межі прототипу

Форма не має backend/API: введення не надсилається, не зберігається й не журналюється. Використовуйте лише вигадані дані. Телефон перевіряється буквально як `+380` та дев’ять ASCII-цифр, без trim/маски; ім’я й повідомлення рахуються графемами. Success dialog прямо повідомляє, що дані не надсилалися.

Справжні замовлення, оплата й доставка не реалізовані. Повний 5-кроковий демо-квіз і локальне керування демо-підпискою реалізовані. Фото Pexels, карта, YouTube й Time.is — окремі сторонні ресурси із власними запитами; це не надсилання форми. Sandbox годинника залишається `allow-scripts allow-popups`, без `allow-same-origin`. Ліцензії успадкованих ресурсів збережені в assets.

Пакувальник копіює тільки runtime-allowlist, зокрема `js/theme.js`, `js/media-components.js`, `css/media-components.css` та `CREDITS.md`. Звіти, чати, prompts, резервні копії, приватні докази, тести й конфігурація IDE до сайту не входять.

## Публікація

Репозиторій: https://github.com/liubomyrrudyipp2025/tvii-khid-rudyi-pp25-lab10

Сайт: https://tvii-khid-rudyi-pp25-lab10.vercel.app

Конфігурація ЛР12 у `.github/workflows/deploy.yml` запускається після push у `main`: locked install → перевірка форматування → build/package → Python та Node tests → офіційний pinned Vercel CLI. Розгортання не виконується після провалу попереднього кроку. Перед deploy порівнюються перевірений `dist`, повторно зібраний `dist` та `.vercel/output/static`.

У налаштуваннях саме цього репозиторію потрібні secret `VERCEL_TOKEN` і variables `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`. Значення токена не зберігається у файлах; він передається лише в середовище кроку Vercel, не аргументом CLI. `.vercel/` і приватні матеріали виключено з Git. `vercel.json` задає `framework: null`, install `npm ci`, build `npm run package:dist`, output `dist`, HTML Content-Type для `/widgets/clock.shtml` та `git.deploymentEnabled: false`: після застосування конфігурації окремі Git auto-deploy цього проєкту не повинні дублювати Actions.

Наявність workflow не доводить успішного хмарного запуску. Після публікації необхідно перевірити реальний Actions run, його commit SHA, Ready/deployment URL та фактичні production-файли. Публічний сайт і приватний dashboard хостингу — різні речі; локальний PASS не є доказом хмарного релізу.
